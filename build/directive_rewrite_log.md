# Phase 4 — CSI 기반 directive 재작성 로그

`KE_M_*` 항목의 directive 가 원형 라벨 상태여서, 작업 디렉터리의 CSI 원본(`4D_PtD_라이브러리_CSI/*.xlsx`, 1,786 사례)을 근거로 재작성했다. 추출본은 `data/csi_raw.json` 에 있다 — `build/` 는 clean 대상이므로 전거를 그 밖에 둔다.

- 대상: `promoted=TRUE` 인 `KE_M_*` **18건** (TBM 계열은 4-3 에서 통합)
- 재작성 **17건** / 근거 불충분 **1건** / 신설 **1건**
- 행 수 90 → 91 (**삭제 0**)

> **HoC 등급을 바꾸지 않았다.** CSI 재발방지대책에는 여러 등급의 조치가 한 문장에 섞여 있어, 각 항목의 기존 `hoc_level` 에 부합하는 조치만 골라 쓰고 나머지는 배제했다. 무엇을 왜 버렸는지는 아래 '배제' 열에 있다.

## 2. 재작성 불가 — 원본 유지

### `KE_M_Fall_MatHandling_01` — 공학적

- 현재 directive(유지): 안전난간 설치·보강
- CSI 사례: 시스템동바리 이동 중 낙하
- 사유: 재발방지대책이 '부재 마모·변형·부식 여부 확인', '작업 전 체결 상태 점검', '사고사례 교육' 뿐으로 전부 점검·교육(관리적)이다. 이 항목의 등급인 공학적에 해당하는 물리적 조치가 CSI 근거에 없다. 난간·수평재 '설치' 를 끌어오면 원문에 없는 조치를 지어내는 것이 되므로 원본 라벨을 유지한다.
- 조치: `needs_review=TRUE`, note 에 "CSI 근거 불충분 — 사람 재작성 필요"

## 3. 신규 항목 (4-2)

### `KE_C_WARN_01` — 경고

- directive: 슬래브 개구부 덮개 상부에 개구부 위치를 알리는 안전표지와 시인성 도색을 적용하도록 설계도면에 반영
- CSI 사례: 개구부 덮개 이탈로 떨어짐
- 신설 사유: KE_M_Fall_FormErection_01(공학적) 의 근거 CSI 에 경고 등급 설계 대안이 함께 있었다. 등급이 다르므로 기존 항목을 고치지 않고 지시서 4-2 대로 신설한다. 현재 라이브러리의 경고 등급은 3건뿐이다.
- 전거·규칙은 채우지 않았다(`needs_review=TRUE`). 지어내지 않는다.
